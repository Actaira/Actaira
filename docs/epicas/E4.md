# Épica E4: desplegado en producción

**Para Claude Code.** Se ejecuta con `/epica E4`. Antes, lee:

- `CLAUDE.md`;
- `docs/harness/LECCIONES.md`;
- `docs/estado/E3.md`;
- en `docs/PLAN.md`: la sección 3 (ADR 16) y la sección 9 ("actaira.com: la puerta de todo").

## Objetivo

Actaira Cloud en producción en `app.actaira.com`, la web en `actaira.com`, ambas sobre el dominio que ya está en Cloudflare, con despliegue automático, reversión probada y coste sin tráfico medido. **El producto funcionando de verdad, en internet.**

## Prerrequisitos (lo que hace Marcos, con los comandos que le da Claude Code)

- Pedir y activar los créditos de Microsoft for Startups **justo antes del primer recurso** de este paso.
- `az login` y elegir la suscripción de los créditos.
- Registrar la GitHub App de producción.
- Acceso a la zona `actaira.com` en Cloudflare para los registros DNS:
  - `app` (CNAME sin proxy) y `asuid.app` (TXT);
  - los de la web y `status`;
  - los de correo de `mail.actaira.com` que da Azure al añadir el dominio en Communication Services: el TXT de verificación, el SPF (TXT), los dos CNAME de DKIM (`selector1-azurecomm-prod-net._domainkey.mail` y `selector2-...`) y un DMARC `_dmarc.mail` con `p=none` al principio. Todos sin proxy.
- Activar el modo live de Stripe al final.

## Pasos

### Paso 4.1: infraestructura como código en Azure (Bicep y az CLI)

- **Fichero `infra/main.bicep`** con `targetScope = 'subscription'`: crea el grupo de recursos y llama a módulos con `scope: rg`. Se valida con `az deployment sub what-if -l <región>` y se aplica con `az deployment sub create`. Un `infra/parameters.<entorno>.json` por entorno (`staging` y `prod`). Recursos:
  - grupo de recursos en la región elegida;
  - Log Analytics con tope diario de ingesta y retención mínima;
  - entorno de Container Apps con perfiles de carga de trabajo, `workloadProfiles: [{ name: 'Consumption', workloadProfileType: 'Consumption' }]`, y las apps con `workloadProfileName: 'Consumption'`;
  - dos Container Apps (`staging` y `prod`), con **réplicas mínimas a 0**, máximo bajo y configurable, y sondas de salud que no tocan la base de datos;
  - **identidad gestionada asignada por el usuario**, creada antes que las apps. Sus roles `AcrPull` y `Key Vault Secrets User` se asignan en el mismo Bicep con `dependsOn`. Las apps la referencian en `registries[].identity` y en `secrets[].identity`. Con la identidad del sistema, la primera creación fallaría porque el rol aún no existe;
  - **Azure Container Registry Basic.** Así se evita tener que rotar tokens de GHCR para una imagen privada;
  - Key Vault con RBAC y los secretos de la app como referencias a Key Vault;
  - quien despliega necesita permiso para asignar roles (Owner o Role Based Access Control Administrator). La CI de revisiones no despliega infraestructura, solo imágenes y revisiones;
  - recurso de Azure OpenAI con el despliegue del modelo elegido en la zona de datos de la UE;
  - **presupuestos en un módulo aparte, `infra/budgets.bicep`,** que se despliega por separado y nunca bloquea `deploy.sh`. Cost Management no admite algunas ofertas de créditos (la de patrocinio de Microsoft for Startups aparece como no soportada). Si Azure lo rechaza, se anota en el ADR 16 y el control de gasto pasa a ser:
    - el saldo en el portal de patrocinios de Azure, que revisa Marcos;
    - la tabla `budget` de la app;
    - el tope diario de Log Analytics;
    - `maxReplicas` bajo.
- **Región:** antes de fijarla, Claude Code comprueba con az CLI que Container Apps y el despliegue de zona de datos de la UE del modelo están disponibles. Orden: Spain Central, Sweden Central, France Central y Germany West Central. **West Europe no se usa:** tiene restricciones de capacidad para entornos nuevos de Container Apps. Queda en un ADR.
- **Validación:** `az deployment group what-if` antes de cada `create`. Scripts `infra/deploy.sh` y `infra/destroy.sh`, idempotentes.
- **Dominio `app.actaira.com`** con certificado gestionado. En Cloudflare va **sin proxy (nube gris) de forma permanente**, con un CNAME directo al FQDN de la Container App y el TXT `asuid.app`, porque el proxy impide emitir y también renovar el certificado. Si `actaira.com` tiene algún registro CAA, se añade `0 issue "digicert.com"`. Activar el proxy exige un ADR nuevo con certificado propio. Claude Code le da a Marcos los registros exactos.

### Paso 4.2: CI/CD con OIDC

- **Identidad federada entre GitHub y Azure**: registro de aplicación más credencial federada para `actaira/actaira-cloud` y la rama `main`, sin `environment:` porque en repos privados gratuitos no hay entornos. La crea Claude Code con az CLI **después** de que Marcos haga `az login`.
  - **Sujeto inmutable:** GitHub cambió el formato del sujeto OIDC para los repos nuevos. Antes de crear la credencial, Claude Code lee los IDs con `gh api repos/actaira/actaira-cloud --jq '.owner.id,.id'` y usa `repo:actaira@<OWNER_ID>/actaira-cloud@<REPO_ID>:ref:refs/heads/main`, comprobándolo contra la documentación actual de GitHub y de Entra.
  - Prueba de humo de `azure/login` en una rama de prueba antes de seguir.
- **Pipeline:**
  - `make check`;
  - imagen;
  - subida a ACR;
  - despliegue de una revisión en `staging`;
  - pruebas de humo contra `staging`.
- **Producción:** un workflow `workflow_dispatch` que lanza Marcos a mano. En repos privados del plan gratuito no hay entornos ni aprobaciones, y así se evitan.
- **Reversión:** activar la revisión anterior de Container Apps, con un comando documentado.

### Paso 4.3: correo, IA y LLM en producción

- Azure Communication Services Email con el dominio propio **`mail.actaira.com`**, verificado con los registros de Cloudflare (TXT, SPF, DKIM y DMARC). Sin buzón: remitente `no-reply@mail.actaira.com` y `Reply-To` a la dirección de contacto de Marcos, configurada fuera del repo. El `Mailer` respeta los límites de envío; si hace falta más cuota, se pide a soporte de Azure.
- El dominio gestionado de Azure solo en `staging` y pruebas. **Antes de dar la verificación por buena**, `verificador-apis` confirma los nombres exactos de los registros en la documentación oficial actual de Azure.
- Prueba: un correo a una dirección de Marcos pasa SPF, DKIM y DMARC (se mira la cabecera `Authentication-Results`).
- Azure OpenAI con el modelo elegido en la zona de datos de la UE. `make llm-select` se vuelve a ejecutar incluyendo los candidatos de Azure (ver `docs/LLM.md`).

### Paso 4.4: web `actaira.com` y página de estado

- Repo `actaira/web`, estático, en inglés y en castellano, desplegado en Cloudflare Pages sobre la zona que ya existe. **Con el harness instalado** con `install.sh` y su propia sesión de Claude Code: `make check` con build, enlaces rotos, `check-weakeners` y `check-fallos`; job `check` obligatorio en la CI.
- **Páginas:**
  - inicio con lo que hace el producto y el enlace a la plataforma;
  - documentación de la CLI y la Action;
  - precios;
  - seguridad con `/.well-known/security.txt` (con `Expires`), con la dirección de contacto configurada (nunca escrita en el repo);
  - aviso legal (LSSI, con los datos que dé Marcos), privacidad, condiciones, DPA con la lista de subencargados y cookies (solo la de sesión).
- **Nada de lo que prometía la web anterior.**
- `status.actaira.com`: una comprobación programada que no toca la base de datos.

### Paso 4.5: pruebas de humo en producción y reversión

- `make smoke-prod`: alta de un inquilino de prueba, subida de un lockfile de `demo-agent`, diff en la consola, correo de alerta y pago en modo test en `staging`.
- Reversión a la revisión anterior de Container Apps, probada.
- Coste de Azure sin tráfico medido durante un periodo y publicado en `docs/estado/E4.md`.

## Riesgos conocidos que ya están resueltos en esta épica


| Riesgo de bloqueo | Cómo queda evitado |
|---|---|
| La nube no puede importar paquetes `internal/` del núcleo | El núcleo expone `pkg/` desde la E1 |
| En repos privados gratuitos no hay protección de ramas, entornos ni aprobaciones | Producción con `workflow_dispatch`, hook `pre-push` y credencial federada atada solo a `main` |
| El sujeto OIDC nuevo de GitHub no coincide con credenciales federadas de formato clásico | Sujeto inmutable con los IDs de owner y repo, y prueba de humo |
| Los presupuestos de Azure no se admiten en suscripciones de créditos | Módulo aparte que no bloquea el despliegue, más controles propios |
| La identidad del sistema no existe al crear la app | Identidad asignada por el usuario, creada antes y con los roles asignados |
| Rol de Neon con `BYPASSRLS` que deja el RLS sin efecto | Rol creado por SQL con `NOBYPASSRLS` y comprobación en la CI |
| La cuota gratuita de Neon se agota por sondas y latidos | Sondas que no tocan la base, escrituras por lotes y cálculo previo en el ADR |
| West Europe sin capacidad para entornos nuevos | Orden de regiones sin West Europe |
| Uso de nombres de repo mutables en el OIDC | IDs de repo y owner, historial de PR separado y rechazo de `jti` repetidos |
| Tirar de una imagen privada de GHCR exige un token que caduca | ACR Basic con identidad gestionada, pagado con créditos |
| El certificado gestionado no se emite ni se renueva con el proxy de Cloudflare | Registro sin proxy de forma permanente |
| Los créditos caducan antes de usarse | Se activan justo antes del primer recurso de Azure |
| Arranque en frío de Container Apps y de Neon | La Action no falla si la nube tarda; Stripe reintenta los webhooks; se responde rápido y se procesa después |
| El modelo elegido no está en la zona de datos de la UE o no hay cuota | Comprobación previa con az CLI; `llm-select` incluye un segundo proveedor (Mistral), así que siempre hay alternativa |
| Log Analytics dispara el coste | Tope diario de ingesta y retención mínima |
| Crear el registro de aplicación de Entra exige permisos | Marcos es propietario de su inquilino; si falla, Claude Code le da el comando exacto para asignarse el rol |
| Stripe live no se activa sin verificar la identidad | Todo se desarrolla en modo test; el live es un paso de Marcos al final |
| Facturación española (Verifactu) | Decidida por Marcos con su asesoría; el código solo depende del puerto `Billing` |
| La verificación del dominio de correo se atasca | El puerto `Mailer` admite un proveedor alternativo |
